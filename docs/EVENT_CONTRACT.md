# TactiFrame candidate event contract (v2)

`run_pipeline.py` writes the observation session. Run `detect_events.py --run-dir <session>` to add `events.json` and `clips/` from those observations. Each file in `events.json` points to a clip in the same session. The source match recording and these derived clips are local simulation and education material only.

Each event has `id`, `type`, `status`, `startFrame`, `endFrame`, `startSeconds`, `endSeconds`, `zone`, `trackIds`, `confidence`, `detector`, `evidence`, and `limitations`. Frames are zero-based in the working copy; seconds are relative to that copy. `status: candidate` means that the event was generated by a rule and has not been manually verified.

`confidence` is a transparent, uncalibrated rule-support score from 0 to 1. It combines sustained observed frames and average distinct player-track occupancy. It is **not** a probability that an event is tactically correct. `detector` records the detector name, version, and thresholds that produced the record.

`evidence.clipPath` is relative to the run folder and includes two seconds of context on either side where available. `evidence.startFrame`, `endFrame`, `startSeconds`, `endSeconds`, and `frames` describe the exported clip. `evidence.eventStartSeconds` and `eventEndSeconds` repeat the event window within that clip context.

`zone.id` is `r0c0` through `r2c2` on a 3×3 grid of **image coordinates**. `zone.coordinateSystem` is always `image_relative_3x3`. This is not a calibrated pitch location. Camera pans and zooms change what a zone means tactically.

The initial types are deliberately visual observations:

- `zone_density`: at least four distinct tracked players in one image zone for at least four seconds of observed frames.
- `zone_contest`: at least two provisionally labeled players from each team in one image zone for at least four seconds of observed frames.

Gaps up to 0.4 seconds are tolerated. Neither type asserts possession, a pass, a turnover, pressure, or a tactical recommendation. Team labels, track continuity, and ball candidates still require validation. A later calibrated pitch map or verified ball path should get a new coordinate-system or event-contract version rather than silently changing these meanings.
